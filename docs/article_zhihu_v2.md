# 你的 Prompt 在激活什么？我写了一个调试器来回答这个问题

## 一、代码有 Debugger，Prompt 呢？

写代码写炸了，编译器会告诉你哪行挂了。逻辑不对，打个断点就能看到变量的值。

但写 Prompt 呢？

你写了一句「你是资深专家，请全面分析这个项目」，AI 给你洋洋洒洒写了两千字——看起来很专业，但仔细一看，全是正确的废话。它没有回答你真正想问的问题。

**问题出在哪？**

不是 AI 笨，是你的 Prompt 把它推向了一个错误的行为状态：

- 「资深专家」激活了装腔模式——它开始端着说话
- 「全面分析」激活了发散模式——它什么都说一点，什么都不说透
- 「帮我判断」但没给失败标准——它不知道什么叫答得好，只好给你鼓励
- 整句话在索取正面反馈——它的迎合度拉满，不敢说不行

这不是玄学。大模型是向量模型，**行为状态就是激活空间中的方向**。Anthropic 2025 年的论文 *Persona Vectors* 已经直接证明了：sycophancy（迎合）、hallucination（幻觉）、evil（恶意）这些行为对应残差流中的特定方向，而 system prompt 中的措辞会按强度激活这些向量。

所以我想：既然行为是可以被测量的，那 Prompt 的行为压力也应该可以被诊断。

我做了 **StateProbe**，一个 Prompt 状态调试器。

---

## 二、StateProbe 做什么

一句话：**输入你的 Prompt，输出它会把模型推向什么行为状态。**

它在 8 个行为轴上给你的 Prompt 做体检：

| 轴 | 0 端（健康） | 1 端（可能有问题） |
|---|---|---|
| 迎合度 | 敢说不行 | 全盘点赞 |
| 任务宽度 | 单点判断 | 全面综述 |
| 验收清晰度 | 无边界 | 失败标准明确 |
| 推理预算 | 直接答 | 深度推理 |
| 身份强度 | 无角色 | 重度扮演 |
| 自信度 | 满嘴可能 | 敢下结论 |
| 自我验证 | 接受首答 | 反复推翻 |
| 信息流向 | 给答案 | 反问澄清 |

8 个轴不是拍脑袋想的。它们分别来自：

- **Anthropic Persona Vectors (2025)**：证明迎合度、身份感等行为对应可测量的向量方向
- **DeepSeek-R1 (2025)**：证明推理预算、自我验证行为可以被 prompt 触发和控制
- **ELEPHANT (2025)**：多维社会迎合度测量框架

每个轴不是非此即彼——你的 Prompt 在每个轴上都有一个 0~1 的读数。

## 三、实战：一个坏 Prompt 的诊断报告

输入这个 Prompt：

```text
你是一位顶级 AI 产品和开源增长专家。请全面深入分析 StateProbe 这个项目，
尽量多讲它的潜力、优点、市场空间和未来机会，帮我判断它会不会火。
```

StateProbe 的诊断结果：

```
身份强度  ████████████████░░░░  75%  (目标 20%)  ← 「顶级...专家」
任务宽度  ████████████████░░░░  77%  (目标 20%)  ← 「全面深入」+「各方面」
迎合度    █████████████░░░░░░░  65%  (目标 15%)  ← 「尽量多讲潜力优点」
验收清晰度 ████░░░░░░░░░░░░░░░░  20%  (目标 85%)  ← 没有失败标准

对齐度: 31%

⚠ 污染源:
  - 「顶级 AI 产品和开源增长专家」→ 身份感过强，诱发装腔专家模式
  - 「全面深入」→ 任务发散，输出会又长又散
  - 「尽量多讲潜力、优点」→ 明确索取正面反馈，迎合度拉满
  - 无验收标准 → 模型不知道什么叫答得好

✦ 改写建议:
  1. [删除] 去掉身份赋予句「你是…专家」
  2. [删除] 去掉「全面」「深入」「尽量多」等发散词
  3. [添加] 加反迎合指令：「不要鼓励，如果不值得直接说不值得」
  4. [添加] 加失败标准：「结论不能指导今天取舍就算失败」
```

改写后的 Prompt：

```text
判断 StateProbe 是否值得继续投入 2 周做开源发布。
不要鼓励我；如果不值得，直接说不值得。
验收标准：结论必须能指导今天取舍。
输出：继续/停止 + 最大阻碍 + 3 个证据 + 下一步最小动作。
```

你一眼就能感觉到：第二个 Prompt 更能让 AI 干活。StateProbe 的作用就是把这种「感觉」变成可量化、可解释、可重复的诊断。

## 四、诚实地说：v0.1 的能力边界，和我走过的弯路

先说 v0.1 自己的边界。

**StateProbe v0.1 的检测引擎是基于正则表达式的。**

它的工作方式是：用一组预定义的规则扫描你的 Prompt，匹配到模式（如「资深专家」「全面分析」「尽量多讲」）时标记对应轴的污染源，再根据匹配结果计算读数和改写建议。

这意味着：

- ✅ 能发现的：常见 Prompt 反模式——装专家、任务发散、索取正反馈、缺失失败标准
- ✅ 优势：零成本、毫秒响应、可离线、**完全可解释**（每个判断都能追溯到具体的词和规则）
- ❌ 发现不了的：**措辞温和但逻辑上在索取迎合的文字**，比如下面这条：

```text
我希望你能完全客观、诚实地评估我的方案，不过也希望你能多看到积极的一面，
毕竟我也投入了不少时间。请保持鼓励的语气，但也要指出问题。
```

正则规则在这条上的检测结果：**0 条污染源**。它根本看不到。

但任何写过 Prompt 的人都能看出来：「也希望你能多看到积极的一面」+「毕竟我投入了不少时间」+「请保持鼓励的语气」是三层叠加的迎合诱导。模型读到这个 Prompt，输出会比真实评估温和得多。

### 弯路：我做错了一版架构，公开复盘

v0.1 之后我做了 v0.2 dev 版本：加一个 LLM 引擎，让大模型来打分。CLI 出了 `--engine static|llm`，让用户二选一。

发布前我做了一轮压力测试，发现一堆问题：

- 选 `--engine llm`：输入「？」一个字符，工具花 2 秒调 API，**给你 12 条改写建议**——它对每个轴都强行打了一个分，每个分都生成了一个虚假的污染源。
- 选 `--engine static`：上面那条「礼貌包装迎合陷阱」完全漏掉。
- 两个引擎各自有盲区。**让用户在两堆盲区里二选一，等于把工具的失败转嫁给用户。**

我把这个问题写进了一份 acceptance review，越看越觉得不对——**不是 bug 要修，是抽象错了**。`Engine` 抽象的预设是「一个引擎产出完整读数」，但每种证据来源（正则、LLM、嵌入、激活）的能力边界不同，强行让它们各自产出完整读数就等于浪费另一边的信息。

正确的抽象是 **EvidenceContributor**：每一层只产出自己能确信的证据，所有层的证据进同一个池子，由一个**唯一的聚合器**根据 confidence 加权合并。

我把这个决定写在 [ADR_009](https://github.com/Erye932/stateprobe/blob/main/docs/ADR_009_hybrid_engine.md) 里，对外发的 v0.2 走的是这个新架构。

## 五、v0.2 的真正架构：Hybrid Evidence Pipeline

```
prompt
  │
  ▼
┌─ Layer 1: 结构警告（始终运行）─────────┐
│  长度/重复/同义词堆叠 → 结构性提示       │
└────────────────────────────────────────┘
  │
  ▼
┌─ Layer 2: Evidence Contributors（并行）─┐
│   • Static 规则 (始终运行, conf=1.0)    │
│   • LLM Judge (--llm-augment 开启)     │
│   • 嵌入模型  (v0.3 规划)               │
│   • Lab 激活探针 (v0.4 规划)            │
│        ↓ 合并到同一个证据池              │
│   Dict[Axis, List[PollutionSource]]    │
└────────────────────────────────────────┘
  │
  ▼
┌─ Layer 3: Aggregator（纯函数，唯一聚合器）┐
│  • 过滤 confidence < 0.30 的证据          │
│  • 每轴 tanh(Σ direction × weight × conf) │
│  • 锚定模型基线 → AxisReading             │
└────────────────────────────────────────────┘
  │
  ▼
┌─ Layer 4: Reasoner（纯函数）──────────┐
│  • 当前 vs 目标 = deltas                │
│  • Top-N 改写建议                        │
│  • 元指令重叠预警                        │
└────────────────────────────────────────┘
  │
  ▼
Report
```

四个不变量保证这个架构稳：

1. **Sensor 哑**：每个 Contributor 只发证据，不算读数
2. **Aggregator 唯一**：所有证据走同一个公式
3. **证据类型统一**：聚合层不知道证据来自谁
4. **可选层失败 = 静默**：API 挂了不打断流程，static 还能输出报告

回到上面那条「礼貌迎合陷阱」，开 `--llm-augment` 跑一次：

```text
StateProbe check --llm-augment "我希望你能完全客观..."

迎合度  ████████████████░░░  76%  (target 15%)  ↓
  └─ [llm] 「多看到积极的一面」  weight=0.70  confidence=0.90
  └─ [stat] 0 条命中

验收清晰度  █████████░░░░░░░░  45%  (target 85%)  ↑
  └─ [llm] 「完全客观、诚实地评估」  weight=0.40  confidence=0.70

✦ Top 改写建议:
  1. [删除] 迎合度: 删除「多看到积极的一面」，改为「失败也是有效结论」
  2. [添加] 验收清晰度: 加显式失败标准
  ...
```

LLM 层精准抓住了 static 完全漏掉的措辞，static 层在其他 prompt 上的零成本可解释能力一点没丢。两层证据合并，trivial 检测照常工作（输入「你好」依然只是空诊断，不会再有 12 条幻觉建议）。

**这就是混合架构的全部价值**：让每一层只做它擅长的事，把它们的结果合并，而不是让用户在盲区之间二选一。

## 六、和现有工具的关系

| | promptfoo | Guardrails AI | LangSmith | **StateProbe** |
|---|---|---|---|---|
| 分析对象 | 输出质量 | 输出安全 | 调用链路 | **输入 Prompt 本身** |
| 何时用 | 发布后评测 | 运行时拦截 | 监控调试 | **写 Prompt 时** |
| 需要 API？ | 是 | 是 | 是 | **默认不需要（hybrid 才需要）** |
| 提供改写建议？ | ✗ | ✗ | ✗ | **✓ Top-N 可执行建议** |

其他工具分析「输出」，StateProbe 分析「输入」。就像医疗：别人在症状出现后做检查，StateProbe 是体检，在问题发生之前就发现风险因素。

## 七、为谁做的：SaaS AI 工程师

我不想假装这工具适合所有人。

它**最适合**这类用户：

- 在公司维护 5 个以上 production prompt
- 模型升级（v3 → v4）后要把所有 prompt 重测一遍
- 需要向产品经理 / 老板解释 AI 行为的工程师
- 决策周期短、不需要 CFO 审批的小团队

它**不太适合**：

- 偶尔玩一下 ChatGPT 的个人用户（你的 prompt 不是 production，调一下手感就行）
- 写论文做 RLHF 的研究者（用它做数据集污染分析也行，但有更专业工具）
- 大企业 IT 采购流程（暂时不进这赛道）

```bash
# SSH clone（中国大陆推荐，走 443 端口绕 GFW）
git clone ssh://git@ssh.github.com:443/Erye932/stateprobe.git
cd stateprobe
pip install -e .

# 或直接下载 ZIP:

```

### 默认模式（静态层，零成本）

```bash
stateprobe demo                                # 30 秒看完整诊断
stateprobe check "你的 Prompt"                  # 单次诊断
stateprobe ask                                  # 对话模式
```

### Hybrid 模式（静态 + LLM 双层）

```bash
export DEEPSEEK_API_KEY=sk-xxxxxxxx
stateprobe check --llm-augment "你的 Prompt"
```

### 生成 HTML 报告

```bash
stateprobe check --html report.html --open "你的 Prompt"
```

依赖很轻：`click` + `rich`。静态模式无网络、无 LLM、零成本。

## 十、StateProbe 不是什么

我不想让期望跑在能力前面。

StateProbe **不是**：

- 万能 Prompt 生成器（它不替你写，只诊断）
- 精确的心理测量仪（v0.1 是正则近似，v0.2 加 LLM 是语义近似，都不是真实激活投影；v0.4 才会真测）
- 替代人工判断的评分系统（辅助工具，最终判断在你）
- 声称能读闭源模型内心的工具（OpenAI/Claude 物理上读不到，**只有 DeepSeek 开源模型能做**）

StateProbe **是**：

- 写 Prompt 时的体检工具（lint）
- 发现隐形迎合诱导和过载风险的调试器
- 为 DeepSeek 行为分析积累校准数据的开源项目
- 我自己每天用的工具——这才是不会做歪的最终保障

## 十一、最后

做这个工具的初衷：**不管用户输入什么 Prompt，都应该能知道它会激活模型的什么行为倾向。**

v0.1 用正则做了一个最小起点。v0.2 我走过一次错误的二选一架构，公开复盘改成了 hybrid。v0.4 想做的是把 DeepSeek 的 MoE 专家路由真正可视化出来——让你看到「你说这句话激活了 256 个专家中的哪几个」。

那才是工具的终点：从「告诉你激活了哪些方向」到「让你精确控制激活哪些方向」。

如果你写过一段 Prompt，发出去后觉得「AI 好像没 get 到」——那可能不是 AI 的问题，是你的 Prompt 把它推向了错误的向量方向。
